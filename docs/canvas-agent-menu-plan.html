백엔드는 이미 세션별로 나뉘어 추적 중이라 새로 만들 게 없습니다. 필요한 건 셋 — 프론트 다중 렌더링, 차단 전용 포즈 1종, 알림 배선.

어길 수 없는 디자인 헌법

기능을 더할 때마다 화면 고정 UI가 하나씩 늘어나는 것이 지금까지 문제의 근원이었습니다. 그래서 규칙을 말이 아니라 수치로 검사 가능하게 못 박습니다. 1~9조는 화면 안을 다루고, 10조 하나만 화면 밖을 다룹니다.

차단 상태만은 화면 밖에도 알린다

앞의 아홉 조는 전부 화면 안의 신뢰를 다룹니다. 그런데 이 제품의 가치는 “화면을 안 보고 있을 때”에 있습니다. 그래서 승인 대기(막힘) 하나만 예외로 둡니다 — 브라우저 알림·소리·푸시로 화면 밖까지 나갑니다.

필요 조건 — Node 22 이상, 로그인된 Codex CLI. 없으면 AI가 먼저 설치하도록 지시
명령 순서 — 의존성 설치 → 빌드 → Companion 실행 → 웹 실행. 각 단계의 성공 기준을 함께 명시

흔한 실패와 대처 — 포트 충돌, Node 버전 미달, Codex 미로그인 세 가지의 증상과 해결을 미리 적어둔다

②번 경로가 새로 안고 가는 것
  • AI 세팅은 매번 같지 않다. 100명이 돌리면 100가지 상태가 나올 수 있어 “되는데 왜 저기선 안 되지”가 생긴다 → npm test 통과를 완료 기준으로 못 박아 상태를 수렴시킨다
  • 실패하면 영어 에러가 그대로 보인다. 우리 화면이 아니라 AI 창에서 터지므로 통제가 안 된다 → 흔한 실패 3종의 해결법을 AGENTS.md에 미리 적어 AI가 스스로 복구하게 한다
  • 대상이 좁아진다. AI 코딩 도구를 이미 쓰는 사람만 ②를 쓸 수 있다 → 나머지는 ①번 데모로 붙잡고, 수요가 확인되면 ③을 만든다
  • 브라우저의 로컬망 접근 제한은 경로와 무관하게 그대로 남는다 → 보안 중계를 유일한 기본값으로 유지한다

경로를 바꿔도 남는 단 하나의 기술 난관

브라우저의 로컬망 접근 제한. 공개 웹페이지가 내 PC 주소로 직접 연결하려 하면 브라우저가 매번 권한 팝업을 띄우고 우회할 방법이 없습니다. 그래서 보안 중계를 보조가 아니라 유일한 기본값으로 승격합니다. 이 경로로 가면 팝업 자체가 발생하지 않습니다. (기존 기획서의 “로컬 직결이 이미 완성돼 동작 중”이라는 서술은 이 사실이 반영되지 않은 것이라 철회합니다.)

이 항목만은 설치 방식과 무관하게 남으므로, ②번 경로로 가더라도 AGENTS.md의 세팅 절차가 보안 중계를 기본으로 구성하도록 지시해야 합니다.

개발자 생산성 도구에서 코스메틱으로 매출을 낸 전례도 조사 범위 안에서 찾지 못했습니다. 이 장르는 “예뻐서”가 아니라 “이거 없으면 일이 막혀서” 지갑을 엽니다. 그래서 무료는 개인 1세션까지 넓게 뿌리고, 유료는 여러 개를 동시에 굴리거나 · 자리를 비우거나 · 여럿이 같이 쓰는 순간에 맞춥니다.

가격 감 — 개인 Pro 월 $8~15(원격 푸시 + 4세션 + 30일 이력). 참고로 Cursor Pro $20, Sentry Team $26~29이므로 그보다 낮게 잡아 진입 장벽을 최소화합니다. 팀은 좌석당 월 $15~25 + 권한 분리·감사로그·중앙 청구.

차단선 유료 결제 항목 전부는 예외 없이 외형·용량·감사 표시에만 관여합니다. AI 응답 속도·품질·승인 우선순위·처리 순서에는 어떤 코드 경로로도 관여하지 않습니다. 도토리를 현금으로 사는 경로도 만들지 않습니다 — 이 두 문장이 지켜지면 균형 조정이라는 작업 자체가 필요 없어집니다.

MoR을 1순위로 검토합니다. 소액 결제는 건당 정액 수수료가 마진을 크게 깎으므로 최소 결제 단위를 그에 맞춰 설계합니다.
후원과 판매의 구분
후원에 리워드를 얹는 순간 유상 거래로 재분류되어 부가세·통신판매업·청약철회 규정이 그대로 적용됩니다.
후원은 리워드 없는 순수 감사 화면으로 고정하고, 진입점·약관·결제 흐름을 판매와 물리적으로 분리합니다.
게임물 해당 여부
‘고양이 꾸미기 + 세션 시각화’가 게임물로 분류되는지는 선례가 불분명해 사안별 판단이 필요합니다.
등급분류기관에 사전 질의하거나 게임 전문 자문을 받아 조기에 확정합니다. 이 판단에 따라 규제 프레임 전체가 갈립니다.
⚖️

이 문서는 법률 자문이 아닙니다

유료화 착수 전 변호사·세무사 검토가 필요합니다. 특히 게임물 해당 여부와 선불전자지급수단 등록 예외 자가판단 두 항목은 오판 시 행정·형사 리스크가 있어 전문가 확인이 필수입니다. 면제 기준 수치(거래 20회·1,200만원 등)는 고시·시행령이라 개정될 수 있으므로 실제 유료화 시점에 최신 기준을 다시 확인해야 합니다.

21 · PAYMENT-READY HOOKS

1단계에서 미리 파묻는 구조

사용자 눈에는 전혀 보이지 않지만, 이것을 안 해두면 2단계에서 소급 재설계 비용이 발생합니다. 반대로 해두면 2단계는 “준비중 배지를 떼는 일”이 됩니다.

21
01크레딧 원장 스키마추가만 되는 거래 테이블 + 중복 방지 키에 고유 제약 + 잔액을 필드로 갱신하지 않고 거래 합으로 파생시키는 구조. 1단계에는 화면도 지급도 없지만 마이그레이션만 미리 넣습니다.
02매점 소품 좌표 슬롯섬 배치 좌표와 모델 슬롯 하나를 미리 예약하되 1단계에서는 렌더링하지 않습니다. 실물 모델을 넣을 때 섬 레이아웃을 다시 짜지 않아도 됩니다.
03상점 카테고리 라우팅꾸미기·소모품·후원·토큰 4개 라우트와 빈 상태 컴포넌트를 미리 만들되 결제 버튼 컴포넌트는 넣지 않습니다.
04생년월일 필드가입 폼에 필드만 넣고 1단계에서는 어떤 기능도 이 값으로 분기하지 않습니다. 2단계에서 조건문만 추가하면 됩니다.
05약관 내 가상재화 조항“가상 재화는 유상 결제 시 환불이 제한될 수 있고 유효기간이 있으며 서비스 종료 시 소멸한다”를 1단계 약관에 미리 넣어 청약철회 예외 고지 근거로 재사용합니다.
06도토리 적립 루프1단계에서 적립만 가동합니다. 출시일에 이미 도토리를 모아둔 사용자가 존재하는 상태로 상점을 열면 첫날 전환이 크게 달라집니다.
07확인쪽지 컴포넌트1단계의 “되돌릴 수 없는 동작” 쪽지를 결제에서도 그대로 재사용할 수 있도록 문구만 주입받는 구조로 만듭니다. 결제 전용 모달을 새로 만들 필요가 없어집니다.
22 · ROLLOUT ORDER

상점 골격부터 결제 연동까지

화면과 약관을 먼저 완성하고 결제는 맨 마지막에 붙입니다. 실결제 계약 전에 준비를 끝내두면 계약 후 리드타임이 짧아집니다.

  • ★ 이력 영속 저장(SQLite 등) + 조회 화면 — 유료 보존 기간을 팔려면 저장부터 있어야 함

  • 미성년자 결제 게이트 설계
  • 확률형 배제 원칙 문서화
  • 결제사 로고 흑백 라인 재도안
