Codex App Server

✓
왜 이 방식인가: 브라우저가 .codex/sessions나 인증 파일을 직접 읽지 않고, 공식 App Server 프로토콜만 사용합니다. 저장 세션이 약 3.1GB로 확인된 현재 환경에서도 원본 JSONL 전체를 직접 파싱하지 않아 더 안전하고 확장성이 좋습니다.

1차: 같은 PC에서 연결

Companion을 실행한 뒤 웹에서 6자리 연결 코드를 입력합니다. 성공하면 내 PC의 최근 세션이 목록에 표시됩니다. 공개 사이트에서 로컬 주소 접근이 브라우저 정책상 막힐 경우 Companion이 로컬 전용 화면을 여는 방식을 예비 경로로 둡니다.

2차: 외부·모바일에서 연결

PC가 보안 중계 서버로 먼저 암호화된 연결을 만들고, 휴대폰은 같은 중계 서버를 통해 접근합니다. PC에 외부 포트를 열지 않는 아웃바운드 연결 방식으로 별도 단계에서 구현합니다.

User experience

사용자는 이렇게 쓰게 됩니다

01 · 연결 PC에서 Companion 실행 → Agent Forest에서 6자리 코드를 입력해 이 브라우저를 연결합니다.
02 · 세션 선택 최근 세션을 프로젝트, 상태, 수정 시간으로 확인하고 최대 4개를 섬의 고양이에게 배정합니다.
03 · 실시간 관찰 Codex의 명령 실행, 파일 수정, 검색, 대기, 완료 상태가 고양이의 장소·행동·말풍선에 반영됩니다.
04 · 작업 제어 대기 중이면 새 작업을 보내고, 실행 중이면 추가 지시를 보내거나 중단할 수 있습니다.
05 · 승인 실제 명령·파일 변경·권한 요청이 화면에 뜨며, 상세 내용을 확인한 뒤 승인 또는 거절합니다.
06 · 재접속 브라우저를 새로 열어도 선택한 세션과 마지막 상태를 복구하고 이어서 확인합니다.

Security baseline

반드시 지킬 보안 원칙

필수 범위
  • App Server는 네트워크에 직접 공개하지 않음기본 연결은 Companion 내부의 stdio만 사용합니다.
  • 로컬 연결도 페어링 필수공개 웹페이지가 무단으로 localhost를 호출하지 못하게 기기 토큰을 요구합니다.
  • 인증 파일·원본 세션 파일 비공개auth.json, 토큰, 전체 transcript를 브라우저로 보내지 않습니다.
  • 승인 정책 유지웹 연결을 이유로 sandbox 또는 승인 단계를 자동으로 완화하지 않습니다.
  • 승인 요청별 정확한 응답요청 ID, 명령, 대상 파일, 권한 범위를 보여주고 해당 요청에만 응답합니다.
  • 민감 정보 필터경로, 환경 변수, 명령 출력, 오류 메시지에서 비밀값을 가립니다.
  • 한 세션의 쓰기 소유자는 하나동시에 여러 화면이 같은 세션에 명령을 보내는 충돌을 막습니다.
  • 외부 연결은 아웃바운드 중계PC 포트를 인터넷에 열지 않고 TLS 기반 보안 중계를 사용합니다.

후속 단계

주요 코드 변경 대상

bridge/server.mjs, bridge/event-mapper.mjs, app/page.tsx를 확장하고 App Server 클라이언트·세션 레지스트리·프로토콜 어댑터를 추가합니다.

Windows 운영 제약

현재 설치 버전에서 App Server daemon lifecycle은 Windows를 지원하지 않습니다. 따라서 Companion이 App Server 자식 프로세스를 직접 시작하고 장애 시 재시작해야 합니다.

Acceptance criteria

MVP 완료 판정 기준

  • 세션 발견현재 PC의 최근 세션 20개를 프로젝트·수정일 기준으로 표시합니다.
  • 실시간 반영선택한 세션 상태가 1초 안에 해당 고양이에게 반영됩니다.
  • 세션 재개대기 중인 저장 세션을 선택해 새 작업을 정상 전송합니다.
  • 작업 스트리밍명령·파일 변경·도구 사용·완료 상태가 순서대로 표시됩니다.
  • 승인 왕복실제 승인 요청을 확인·응답한 뒤 Codex 작업이 계속 진행됩니다.
  • 중단 기능활성 작업을 UI에서 중단하고 최종 상태를 정확히 표시합니다.
  • 재접속 복구새로고침 후 선택 세션과 마지막 이벤트 스냅샷이 복원됩니다.
  • 보안 검증페어링 없는 공개 페이지에서 로컬 Companion을 제어할 수 없습니다.
Decision log

착수 전 확정할 기본 방향

기본 연결

권장: 같은 PC + Companion + App Server stdio. 가장 안정적이고 노출 면적이 작습니다.

세션 개수

권장: 처음에는 선택 세션 최대 4개. 현재 섬의 컴퓨터 작업 공간과 자연스럽게 대응합니다.

독립 TUI

원칙: 기존 실행 프로세스를 탈취하지 않고, 저장 세션을 재개하거나 처음부터 Companion 관리하에 시작합니다.

외부 접속

원칙: MVP 이후 보안 중계 방식으로 추가. localhost 직접 공개는 하지 않습니다.

개발 착수점

첫 작업: Phase 0에서 실제 세션 1개를 읽고 상태 이벤트를 고양이 1마리에 연결하는 수직 시제품을 만듭니다.
