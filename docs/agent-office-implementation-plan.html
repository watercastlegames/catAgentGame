01

디자인은 이미 충분히 강합니다.
세 장의 역할만 명확히 나누면 됩니다.

따뜻한 손그림, 숲속 부서 배치, 보고서를 들고 줄을 선 캐릭터만으로 “AI 팀이 실제로 일하고 있다”는 설명이 됩니다. 새 디자인을 다시 만드는 것보다 현재 원화를 제품 화면 체계로 정리하는 편이 효율적입니다.

PRIMARY

1번 · 기본 운영 화면

고양이만 사용해 브랜드 일관성이 가장 좋습니다. 로그인 후 기본 대시보드와 실시간 관제 화면으로 채택합니다.

CORE UX

2번 · 승인·보고 화면

제품의 핵심 장면입니다. 에이전트가 보고하고 사용자가 확인·재검토·반려하는 감독 루프에 사용합니다.

EXPANSION

3번 · 멀티 캐릭터 확장

직업별 종족·스킨·성격을 판매하거나 조직별 테마를 제공하는 2차 확장안으로 보존합니다.

✓V1 디자인 결정

고양이 단일 종족 + 숲속 오피스로 시작합니다. 대표 화면은 1번, 승인 모달과 매니저 연출은 2번을 사용합니다.

↗V2 확장 결정

3번 이미지는 직군별 동물 캐릭터, 유료 스킨 또는 회사별 커스텀 테마가 필요할 때 확장합니다.

02

제품 콘셉트: 로그 대신 살아 있는 팀을 본다

사용자는 복잡한 터미널 로그를 읽지 않고도 어느 부서가 일하는지, 누가 막혔는지, 무엇을 승인해야 하는지 한눈에 파악합니다.

“General에 일을 맡기면 고양이 매니저가 작업을 분배하고, Coding·Design·Music 에이전트가 실제 도구를 사용한 뒤 보고서를 들고 사용자에게 돌아온다.” 화면 속 모든 행동은 서버가 받은 실제 에이전트 이벤트와 연결합니다. 단순 반복 애니메이션은 대기 상태에서만 사용합니다.

⌁월드의 의미

숲은 프로젝트 전체, 부서 표지판은 전문 에이전트 그룹, 책상은 도구 실행, 줄을 선 캐릭터는 완료·승인 대기 작업을 뜻합니다.

☝사용자의 역할

사용자는 오른쪽 아래 개인 사무실의 최종 책임자입니다. 위험한 변경, 외부 발행, 결제 등 중요한 행동만 승인합니다.

◎정보 계층

전체 상태는 월드에서, 상세 작업·비용·로그·산출물은 캐릭터 클릭 패널에서 확인합니다. 예쁜 화면과 실무 정보를 분리합니다.

♢브랜드 주의

Discord를 실제 연동할 때만 공식 로고를 사용합니다. 일반 부서라면 자체 발자국 아이콘으로 교체해 제품 정체성과 상표 리스크를 정리합니다.

03

핵심 사용자 흐름은 여섯 단계면 충분합니다

이 흐름을 먼저 완성하면 캐릭터 수나 부서가 늘어나도 제품 구조가 흔들리지 않습니다.

1

사용자가 목표를 입력

개인 사무실 또는 하단 입력창에서 “서버 업데이트해줘”처럼 자연어로 요청합니다.

PERSONAL OFFICE
2

매니저가 업무를 분해

General 매니저가 작업을 작은 단위로 나누고 필요한 부서에 배정합니다.

GENERAL
3

전문 에이전트가 자리로 이동

에이전트가 담당 책상으로 걸어가며 현재 할 일과 대상 프로젝트를 말풍선으로 표시합니다.

MOVE
4

실제 도구를 사용해 작업

코드 작성, 검색, 이미지 생성, 음악 제작 등 도구 이벤트를 부서별 애니메이션으로 표현합니다.

WORKSTATION
5

완료 보고서가 대기열에 도착

완료한 캐릭터가 보고서를 들고 개인 사무실 앞으로 이동합니다. 긴 줄은 실제 승인 대기 건수를 나타냅니다.

REPORT QUEUE
6

확인·재검토·반려

확인은 종료, 재검토는 피드백과 함께 같은 작업 재개, 반려는 작업 중단과 변경 폐기를 의미합니다.

APPROVAL
04

AI 상태를 캐릭터 행동으로 번역합니다

AI에게 걷는 좌표를 매번 묻지 않습니다. AI는 업무 이벤트만 만들고, 이동 경로와 애니메이션은 게임 상태 머신이 결정합니다.

서버 이벤트 월드 위치 캐릭터 연출 사용자에게 보이는 정보
session.created 숲 입구 등장 → 주변 확인 에이전트 이름·역할
task.assigned 부서 이동 경로 담당 책상으로 걷기 작업 제목·담당 부서
tool.started 부서 작업대 타이핑·그리기·연주 도구 이름·경과 시간
approval.required 개인 사무실 앞 보고서를 들고 대기 승인 사유·예상 영향
task.completed 보고 대기열 완료 배지·짧은 환호 결과 요약·산출물 링크
task.failed 현재 위치 멈춤·경고 말풍선 실패 원인·재시도 버튼
agent.idle 휴식 지점 커피·대화·기지개 대기 중 상태
05

화면과 AI 실행부를 분리해야 오래 갑니다

OpenClaw, Codex, Claude 또는 자체 에이전트를 바꾸더라도 같은 월드 화면을 유지할 수 있도록 모든 실행 이벤트를 공통 규격으로 변환합니다.

▣추천 프런트엔드

React + Phaser. Phaser는 캐릭터·충돌·카메라·애니메이션을 맡고, React는 모달·작업 패널·설정·로그를 맡습니다.

⌘추천 이동 방식

현재 원화는 격자형 사무실이 아니므로 타일맵보다 웨이포인트 경로 그래프가 적합합니다. 입구·부서·대기열·개인 사무실을 노드로 연결합니다.

06

현재 원화에서 여섯 종류의 제작 에셋을 분리합니다

디자인 원화는 훌륭한 아트 디렉션입니다. 다만 캐릭터가 실제로 이동하려면 “동물이 없는 깨끗한 배경”과 “투명 배경 캐릭터”가 반드시 필요합니다.

ASSET 01 빈 숲 배경 캐릭터·표지판·말풍선·글자가 없는 세로형 1696×2528 이상 배경.
ASSET 02 부서 작업대 General 원탁, Coding 책상, Design 작업대, Music 무대를 투명 PNG로 각각 분리.
ASSET 03 캐릭터 스프라이트 걷기 4방향, 대기, 작업, 보고서 들기, 성공, 실패. 상태별 4~8프레임.
ASSET 04 전경·가림 레이어 나무, 책상 앞쪽, 의자 등 캐릭터가 뒤로 지나갈 수 있는 전경 오브젝트.
ASSET 05 매니저 캐릭터 승인 모달에 나타나는 큰 고양이 전신·반신 일러스트와 감정 표정 세트.
ASSET 06 웹 UI 컴포넌트 부서명, 보고 문구, 버튼은 이미지에 굽지 않고 HTML로 구현해 내용 변경과 다국어 지원.
!

현재 PNG를 그대로 움직이는 것은 권장하지 않습니다

캐릭터를 잘라내면 뒤의 잔디와 가구가 비어 보이고, 이미지 안의 글자는 상태에 따라 변경할 수 없습니다. 첫 단계에서 원본 스타일을 유지한 빈 배경과 개별 캐릭터 시트를 다시 제작하는 것이 전체 개발 시간을 줄입니다.

07

단계별 개발 일정

1인 개발 기준의 현실적인 범위입니다. 에셋 제작과 에이전트 연동을 병렬로 진행하면 기간을 단축할 수 있습니다.

PHASE 0 · 2~4일

아트 분해

빈 배경, 부서 오브젝트, 캐릭터 상태표, UI 스타일 토큰을 준비합니다.

PHASE 1 · 3~5일

클릭형 프로토타입

가짜 이벤트로 이동, 작업, 보고 대기열, 승인 모달을 완성합니다.

PHASE 2 · 1~2주

실제 Agent MVP

에이전트 실행 이벤트, WebSocket, 승인 처리, 작업 상세 패널을 연결합니다.

PHASE 3 · 2~4주

제품화

다중 프로젝트, 이력, 알림, 비용 표시, 모바일 최적화와 복구 처리를 추가합니다.

08

첫 버전은 작게, 그러나 실제로 작동하게 만듭니다

초기에 에이전트끼리 자유 대화를 시키기보다, 작업 배정·도구 실행·승인이라는 핵심 생산 흐름의 신뢰성을 먼저 완성합니다.

V1에 반드시 포함

  • 고양이 캐릭터 6~8개와 4개 부서
  • 웨이포인트 기반 이동과 작업 애니메이션
  • 실제 에이전트 상태의 실시간 반영
  • 작업 상세·결과·오류 패널
  • 보고 대기열과 확인·재검토·반려
  • 새로고침 후 작업 상태 복구
  • 민감 정보 마스킹과 서버 권한 검사

V2 이후로 미루기

  • 동물 종족별 능력치와 성장 시스템
  • 자율 채용과 무제한 에이전트 생성
  • 3D 월드 또는 자유로운 가구 편집
  • 에이전트끼리 목적 없는 상시 대화
  • 테마·스킨 마켓과 회사별 커스텀 공간
  • 음성 대화, BGM 제작, 소셜 기능
09

예쁜 화면보다 중요한 네 가지 신뢰 규칙

화면의 캐릭터 상태와 실제 작업 상태가 어긋나면 사용자는 곧바로 제품을 믿지 않게 됩니다.

1. “일하는 척”하지 않기

타이핑 애니메이션은 실제 tool.started 이후에만 재생합니다. 이벤트가 끊기면 작업 중으로 계속 보이지 않도록 타임아웃과 연결 끊김 상태를 표시합니다.

2. 내부 추론 대신 안전한 활동 요약만 노출

모델의 비공개 사고 과정이나 원문 프롬프트를 말풍선에 표시하지 않습니다. “인증 오류 원인 조사 중”처럼 서버가 만든 짧은 활동 요약만 보여줍니다.

3. 승인 버튼의 실제 의미를 서버에서 강제

외부 발행, 파일 삭제, 결제, 운영 서버 변경은 캐릭터 UI를 우회해도 실행되지 않도록 서버 권한 계층에서 승인 토큰을 검사합니다.

4. 모바일에서 정보가 캐릭터를 가리지 않게 하기

기본 화면에는 상태점과 짧은 말풍선만 표시하고, 상세 내용은 하단 시트로 엽니다. 승인 모달이 열리면 배경을 어둡게 하되 현재 담당 캐릭터는 함께 보여줍니다.

10

최종 제안: 1번과 2번을 합쳐 V1을 시작합니다

1번 이미지를 항상 보이는 기본 월드로 사용하고, 실제 승인이 필요할 때만 2번의 매니저와 모달이 나타나게 합니다. 3번 멀티 동물 버전은 제품의 기본 동작이 검증된 뒤 테마 확장으로 전환합니다.
