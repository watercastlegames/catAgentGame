6

격리 작업 폴더와 고정 연결 코드 준비

AI가 Agent Forest 소스 자체를 작업 대상으로 오인하지 않게 사용자 홈 아래 별도 폴더를 사용합니다.

$projectDir = (Get-Location).Path
$workspace = Join-Path $env:USERPROFILE 'AgentForestWorkspace'
if (-not (Test-Path -LiteralPath $workspace)) {
  New-Item -ItemType Directory -Path $workspace | Out-Null
}

$pairingFile = Join-Path $projectDir '.agent-forest-pairing.json'
if (Test-Path -LiteralPath $pairingFile) {
  $pairingCode = (Get-Content -LiteralPath $pairingFile -Raw | ConvertFrom-Json).pairingCode
} else {
  $pairingCode = '{0:D6}' -f (Get-Random -Minimum 100000 -Maximum 1000000)
  @{ version = 1; pairingCode = $pairingCode; tokenHashes = @() } |
    ConvertTo-Json | Set-Content -LiteralPath $pairingFile -Encoding utf8
}

"연결 코드: $pairingCode"

이 파일은 각 PC가 따로 생성하며 Git에 커밋하거나 다른 사람에게 전송하지 않습니다.

7

브리지와 웹 화면을 백그라운드 실행

$env:CODEX_BRIDGE_WORKSPACE = $workspace
$env:AGENT_BRIDGE_PAIRING_CODE = $pairingCode
$bridge = Start-Process -FilePath 'npm.cmd' -ArgumentList 'run','bridge' `
  -WorkingDirectory $projectDir `
  -RedirectStandardOutput (Join-Path $projectDir '.bridge.out.log') `
  -RedirectStandardError (Join-Path $projectDir '.bridge.err.log') `
  -WindowStyle Hidden -PassThru
$bridge.Id | Set-Content -LiteralPath (Join-Path $projectDir '.bridge.pid') -Encoding utf8
Remove-Item Env:\CODEX_BRIDGE_WORKSPACE -ErrorAction SilentlyContinue
Remove-Item Env:\AGENT_BRIDGE_PAIRING_CODE -ErrorAction SilentlyContinue

$web = Start-Process -FilePath 'npm.cmd' -ArgumentList 'run','dev' `
  -WorkingDirectory $projectDir `
  -RedirectStandardOutput (Join-Path $projectDir '.devserver.out.log') `
  -RedirectStandardError (Join-Path $projectDir '.devserver.err.log') `
  -WindowStyle Hidden -PassThru
$web.Id | Set-Content -LiteralPath (Join-Path $projectDir '.devserver.pid') -Encoding utf8

환경 변수는 실행한 브리지 프로세스에만 상속되며 Windows 시스템에 영구 등록되지 않습니다.

07

이후 업데이트 방법

GitHub 전달 방식일 때의 안전한 갱신 순서입니다. 실행 중인 프로세스는 해당 프로젝트의 PID인지 확인한 뒤에만 종료합니다.

git status
git pull --ff-only
npm install
npm test
  • git status에 사용자 변경이 있으면 먼저 백업하거나 커밋합니다.
  • 테스트가 성공한 뒤 기존 bridge/dev PID가 이 프로젝트 것인지 확인하고 재시작합니다.
  • .agent-forest-pairing.json은 유지해야 브라우저 재연결을 최소화할 수 있습니다.
  • ZIP 전달 방식은 기존 폴더 위에 덮어쓰지 말고 새 폴더에 압축을 풀어 검증한 뒤 교체합니다.
08

문제 해결

증상별로 가장 먼저 확인할 항목입니다. 무관한 프로세스나 사용자 파일을 추측으로 삭제하지 않습니다.

“Codex unavailable” 또는 Codex 세션이 없음

codex --version과 codex login status를 확인합니다. npm 전역 설치 경로가 아니라면 npm install -g @openai/codex 설치판을 사용하고 bridge를 다시 시작합니다.

“Claude Code CLI를 찾지 못했습니다”

현재 Windows 브리지는 npm 전역 설치 경로를 찾습니다. 아래 세 명령이 모두 성공해야 합니다.

npm install -g @anthropic-ai/claude-code
claude --version
claude auth status

native Windows에서 Bash 관련 오류가 나오면 Git for Windows 설치와 claude doctor 결과를 확인합니다.

thread/resume 요청 시간 초과
  • 해당 CLI에서 같은 세션을 직접 열 수 있는지 먼저 확인합니다.
  • 오래되거나 손상된 세션이면 Agent Forest에서 새 세션을 생성해 시험합니다.
  • 브리지 로그의 마지막 오류와 CLI 로그인 만료 여부를 확인합니다.
  • 세션 목록 새로고침을 연속 클릭하지 말고 한 번의 요청이 끝날 때까지 기다립니다.
포트 3000 또는 4317이 이미 사용 중

PID 파일의 프로세스가 실제 Agent Forest인지 먼저 확인합니다. 정상 서버라면 그대로 사용하고, 이전 프로젝트 프로세스가 확실할 때만 정상 종료 후 재시작합니다.

Get-Process -Id (Get-Content .bridge.pid) -ErrorAction SilentlyContinue
Get-Process -Id (Get-Content .devserver.pid) -ErrorAction SilentlyContinue
Invoke-RestMethod http://127.0.0.1:4317/health
Invoke-WebRequest -UseBasicParsing http://localhost:3000
6자리 코드를 입력해도 연결되지 않음

현재 PC 프로젝트 루트의 페어링 파일에서 pairingCode 값을 확인합니다. 다른 PC에서 복사한 코드를 쓰면 안 됩니다. 연결 해제 후 현재 코드로 다시 페어링합니다.

웹 화면이 늦거나 처음에 빈 화면으로 보임

첫 vinext/wrangler 콜드스타트와 3D 에셋 로딩에는 수 초가 걸릴 수 있습니다. dev 로그에 실제 오류가 없는지 보고, HTTP 200 확인 후 브라우저를 한 번 새로고침합니다.
