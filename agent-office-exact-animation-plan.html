01

구현 원칙: 재해석하지 않고 분해한 뒤 다시 조립합니다

현재 이미지는 완성 원화로서는 좋지만 모든 물체와 캐릭터가 한 장에 합쳐져 있습니다. 실제 움직임을 만들려면 보이는 모양과 위치는 그대로 유지하면서 내부 구조만 게임용으로 바꿔야 합니다.

≋

선택 방식: 2.5D 레이어 월드 + 프레임 스프라이트

숲과 가구는 여러 장의 고정 레이어로, 고양이는 투명 스프라이트로, 승인 모달과 부서 표지판은 HTML UI로 만듭니다. Phaser가 이동·깊이·애니메이션을 담당하고 React는 현재 작업 패널과 승인 화면을 유지합니다.

✓그대로 유지할 것

  • 1696×2528 세로 화면 비율과 전체 구도
  • 숲 테두리와 중앙 잔디 공간의 색감·명암
  • General·Coding·Design·Music의 상대 위치
  • 왼쪽 보고 대기열과 오른쪽 아래 개인 사무실
  • 둥근 선, 저채도 파스텔, 손그림 느낌과 고양이 비율

!하면 안 되는 것

  • 현재 JPG에서 고양이만 대충 잘라 움직이기
  • 빈 공간 복원 없이 물체를 제거해 잔디가 뚫리게 만들기
  • 부서 위치를 반응형이라는 이유로 임의 재배치하기
  • 글자와 승인 버튼을 다시 배경 이미지에 구워 넣기
  • 원화 검증 없이 캐릭터 전체 세트를 한 번에 생산하기
02

03

한 장의 원화를 여섯 깊이 레이어로 재구성합니다

모든 레이어는 1696×2528 투명 캔버스에 원래 위치 그대로 저장합니다. 실행 시에는 y 좌표 기반 정렬을 더해 고양이가 책상 앞·뒤와 사무실 벽 안쪽을 자연스럽게 오갈 수 있게 합니다.

L10Back Forest상단·좌우 숲 테두리, 뒤쪽 관목과 나무. 월드의 고정 배경.
L20Station Back책상 뒷면, 모니터, 무대 뒤쪽, 개인 사무실 뒷벽·책장.

L40Station Front책상 앞판, 의자 앞쪽, 무대 모서리, 개인 사무실 전면 벽. 캐릭터를 가리는 전경.

◫정적인 장식 캐릭터

원화의 풍성함을 유지하기 위해 부서 주변의 일부 고양이는 짧은 대기 루프를 하는 “오피스 장식 인원”으로 둘 수 있습니다. 이름·상태 배지가 없으므로 실제 AI 에이전트로 오해되지 않게 합니다.

●실제 AI 캐릭터

실제 Codex 세션과 연결된 고양이만 이름, 상태점, 작업 말풍선을 표시합니다. 왼쪽 보고 대기열은 장식으로 채우지 않고 실제 완료·승인 대기 건수와 1:1로 대응시킵니다.

04

원화의 표현을 보존하는 이미지 제작 공정

숨겨진 잔디와 가구 뒷면은 원본에 존재하지 않으므로 단순 자르기만으로는 만들 수 없습니다. 마스크 복원과 수작업 보정을 함께 사용하고, 매 단계마다 원본과 겹쳐 비교합니다.

01 원본 잠금 1696×2528 PNG를 기준 파일로 복사하고 색상 프로필·비율·구도를 변경하지 않습니다.
02 마스크 분할 숲, 잔디, 가구, 캐릭터, 전경, UI를 영역별 마스크로 표시합니다.
03 빈 공간 복원 고양이와 가구 뒤에 가려졌던 잔디·벽·바닥을 인페인팅 후 손으로 보정합니다.
04 레이어 재조립 모든 분리 파일을 원래 좌표에 올려 정지 화면이 원본과 같은지 A/B 비교합니다.
05 움직임 제작 정지 화면 재현 승인 후에만 고양이·모니터·악기·말풍선 애니메이션을 추가합니다.
A/B
필수 관문: Static Reconstruction Gate

레이어 조립 결과를 원본 위에 50% 투명도로 겹쳤을 때 부서 위치, 숲 경계, 가구 실루엣, 개인 사무실 크기가 흔들리지 않아야 합니다. 원본과 나란히 보았을 때 “다른 그림”처럼 느껴지면 해당 레이어를 다시 만듭니다.

✎권장 제작 도구

Photoshop·Affinity Photo·Krita 중 하나로 마스크와 레이어를 관리합니다. AI 편집은 빈 공간 복원 초안에만 쓰고 테두리와 색감은 수작업으로 맞춥니다.

◉색감 기준

원본에서 숲·잔디·목재·고양이 털 팔레트를 추출해 고정합니다. 새 에셋은 같은 팔레트와 좌상단 광원, 갈색 외곽선 굵기를 지켜야 합니다.

05

06

책상과 부서 공간도 원화의 모양 그대로 분리합니다

가구를 새로 배치하지 않습니다. 원화의 가구 실루엣을 유지한 채 캐릭터가 앞뒤로 들어갈 수 있도록 각 작업대를 Back·Seat·Front 세 부분으로 나눕니다.

General · 원탁과 회의 테이블

상단 원탁과 왼쪽 회의 테이블의 위치와 크기를 유지합니다.

  • 테이블 뒷면 / 좌석 앵커 / 테이블 앞면 분리
  • 문서 넘김, 태블릿 확인, 대화 점 말풍선
  • 매니저가 중앙에서 부서 배정을 시작

Coding · 상단·중앙 책상

두 Coding 작업 공간 모두 보존하되 실제 에이전트는 빈 좌석을 선택합니다.

  • 책상, 모니터, 키보드, 의자, 가방 개별 레이어
  • 모니터 빛·코드 스크롤·키보드 손 동작
  • 책상 앞판이 앉은 고양이의 하체를 자연스럽게 가림

Design · 중앙 작업 플랫폼

파란 타원 작업면, 팔레트, 붓통과 목재 단상을 그대로 유지합니다.

  • 단상 / 작업면 / 팔레트 / 붓 / 캐릭터 분리
  • 붓질, 물감 번짐, 완성 이미지 반짝임
  • 작업 산출물 썸네일을 종이 위에 동적으로 표시 가능

Music · 오른쪽 무대

원화의 기타·첼로·악보대와 무대 모서리를 그대로 복원합니다.

  • 무대 뒤 / 악기 캐릭터 / 무대 앞판 분리
  • 악기별 짧은 연주 루프와 HTML/CSS 음표 효과
  • 실제 오디오 작업 중에만 작업 애니메이션 재생

개인 사무실은 하나의 그림이 아니라 네 겹의 컷어웨이 공간으로 만듭니다

현재 원화의 오른쪽 아래 사무실 크기, 목재 벽, 책장, 책상, 모니터, 의자와 원형 러그를 그대로 유지합니다. 사용자를 상징하는 매니저 고양이는 의자에 앉거나 책상 앞으로 나와 보고를 받습니다.

▣승인 화면

2번 원화의 어두운 배경, 큰 매니저 고양이, 크림색 보고 모달과 민트·파랑·코랄 버튼 표현을 React 모달로 그대로 재현합니다.

A텍스트 처리

“보고합니다”, 작업 결과, 부서명은 이미지가 아니라 HTML 텍스트로 표시합니다. 그래야 실제 Codex 결과와 다국어가 들어가도 선명합니다.

07

Phaser는 월드만, React는 업무 UI만 담당합니다

현재 구현된 Codex 브리지와 이벤트 규격은 그대로 사용합니다. 기존 배경 이미지 영역만 Phaser 캔버스로 교체하고, 작업 입력·로그·승인 모달은 현재 React 코드를 유지합니다.

Codex Bridge현재 JSONL·SSE 연동 유지
Event MapperAI 이벤트 → 캐릭터 상태
React Store작업·승인·상태 공유
Phaser World배경·가구·이동·깊이 정렬
React Overlay부서표지·말풍선·승인 모달

AI 실행부를 바꾸지 않고 시각 렌더러만 교체하므로 현재 연동 성공 결과를 그대로 보존할 수 있습니다.

const world = { masterSize: { width: 1696, height: 2528 }, scaleMode: "FIT", crop: false, agentOrigin: { x: 0.5, y: 1.0 }, depthRule: (sprite) => sprite.y, stations: { general: { x: 848, y: 581 }, coding: { x: 1221, y: 860 }, design: { x: 882, y: 1567 }, music: { x: 1289, y: 1315 }, queue: { x: 407, y: 1719 }, office: { x: 1221, y: 2124 } } };

↝이동

격자 타일맵 대신 원화 위에 숨겨진 웨이포인트 경로를 놓습니다. 고양이는 숲과 가구를 관통하지 않고 원화 속 열린 잔디 길을 따라 이동합니다.

↕깊이

고양이의 발 y좌표를 depth로 사용하고 책상 앞판·사무실 벽은 별도 고정 depth를 지정해 원화와 같은 앞뒤 관계를 만듭니다.

▦텍스처

배경은 WebP, 투명 캐릭터와 전경은 PNG 또는 무손실 WebP atlas로 내보냅니다. 한 atlas는 최대 2048×2048로 제한합니다.

60성능

데스크톱 60fps, 저사양 모바일 30fps, 동시에 실제 움직이는 에이전트 8개를 기본 예산으로 잡습니다.

08

원화의 풍성함과 실제 AI 상태의 진실성을 함께 유지합니다

화면을 원화처럼 풍성하게 보이게 하려고 실제로 실행되지 않는 AI를 “작업 중”으로 표시하면 안 됩니다. 장식용 동작과 실제 Codex 이벤트를 시각적으로 구분합니다.

1 실제 에이전트

이름표, 상태점, 작업 말풍선이 있고 Codex의 thread·turn·tool 이벤트와 1:1로 움직입니다.

2 장식용 오피스 고양이

원화 분위기를 유지하는 짧은 대기 루프만 재생하며 이름·업무·진행률을 표시하지 않습니다.

3 보고 대기열

장식 캐릭터를 넣지 않습니다. 줄의 길이는 실제 완료 또는 승인 대기 작업 수와 정확히 일치합니다.

Codex 이벤트월드 행동위치애니메이션

turn.failed문제 보고현재 위치귀 처짐·경고 말풍선

5단계 일정과 각 단계의 중단·승인 관문

1인 제작 기준 약 4~5주입니다. 전체 고양이를 먼저 만드는 대신 한 부서의 완전한 루프로 품질과 기술을 검증한 뒤 확장합니다.

PHASE 0 · 1~2일

원본·스타일 잠금

원본 PNG 확보, 좌표·팔레트·선 굵기·광원 기준서 작성.

PHASE 1 · 4~6일

정지 화면 복원

Clean Ground, 숲, 가구, 사무실을 분리하고 재조립 A/B 검증.

PHASE 2 · 5~7일

Coding POC

고양이 한 마리의 입장·걷기·타이핑·보고·승인 전체 루프.

PHASE 3 · 7~10일

전체 부서 확장

General·Design·Music와 개인 사무실 반응, 캐릭터 변형 추가.

PHASE 4 · 4~6일

통합·최적화

실제 Codex 이벤트, 모바일 성능, 복구·오류·승인 흐름 검증.

G1관문 1

분리 레이어를 모두 꺼내고 다시 켰을 때 원화와 구도·크기·색감이 동일하게 느껴지는지 승인합니다.

G2관문 2

Coding 고양이 한 마리가 원화 스타일을 깨지 않고 책상 앞뒤를 이동해 실제 Codex 완료 보고까지 수행해야 전체 제작을 시작합니다.

시각 합격

스크린샷을 원화와 나란히 봤을 때 숲·부서·가구·사무실의 크기와 위치가 다른 그림처럼 느껴지지 않습니다.

동작 합격

Coding 고양이가 입구에서 등장해 책상에 앉고 실제 Codex 작업 후 보고서를 들고 사무실로 이동합니다.

진실성 합격

작업 중 애니메이션은 실제 이벤트가 있을 때만 재생되고 보고 대기열 수가 실제 승인 대기 수와 일치합니다.

성능 합격

900px 세로 월드에서 초기 이미지 용량 3MB 이하, 데스크톱 60fps, 모바일 최소 30fps를 유지합니다.

착수 순서: 전체 제작이 아니라 “원본 복원 + Coding 한 마리”부터

첫 번째 결과물은 완성 게임이 아닙니다. 원화에서 고양이를 모두 제거한 Clean Ground, Coding 책상의 앞·뒤 레이어, 원화 스타일의 Coding 고양이 한 마리를 제작한 뒤 현재 Codex 이벤트로 전체 루프를 검증합니다. 이 결과가 원화와 자연스럽게 섞이면 같은 규격으로 General·Design·Music와 개인 사무실을 확장합니다.
